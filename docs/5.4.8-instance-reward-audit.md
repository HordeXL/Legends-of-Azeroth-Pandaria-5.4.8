# Instance reward difficulty audit — 2026-10-05

SQL update: `2026_10_05_01_world_instance_reward_difficulties.sql`.

## Findings and changes

The live database mixed Normal, Heroic and Raid Finder item variants in several
boss tables. It also placed six Normal dungeon reward chests in Heroic and three
Dragon Soul 25-player Heroic chests in 10-player Normal.

- Corrected 430 existing creature loot rows: 407 mode changes and 23 wrong-mode
  duplicates removed because the correct-mode row already existed. The selection
  is recorded in `contrib/instance_rewards_548/creature-mode-fixes.csv`.
- Affected tables include the Nexus commanders, Slad'ran, Anub'arak, Selin,
  Kael'thas, Chillheart, Snowdrift, Taran Zhu, the Mogu'shan Palace trial bosses,
  Spirit Kings, Mel'jarak, Tsulong, Lei Shi and Immerseus. These include secondary
  NPC loot tables; not every corrected table is actually exposed as a lootable
  corpse by its encounter script.
- Normal gear, Heroic gear, Raid Finder gear and tier tokens now have distinct
  masks in the reviewed tables. Removed Skadi's extra Normal mount drop; retained
  the existing Heroic chance.
- Normal chest spawns: 185168, 190586, 191349, 195323, 195374, 195709 use mask 2.
- Dragon Soul chests 210163, 209897, 210220 use mask 64 (25-player Heroic).
  Their identities are independently defined in `dragon_soul.h`.
- Removed Heroic weapon 47514 from Paletress's Normal chest. The Heroic chest's
  existing weapon roll remains intact.
- Added missing Dungeon Journal items 5254, 5943 and 6319 to Silverlaine's Normal
  group, and 37649 to Krystallus's Heroic group. They join existing equal-chance
  groups and do not add another loot roll.

No rates, existing row chances, existing group identifiers or stack quantities
were changed. Removing wrong-mode entries and adding missing members necessarily
changes the eligible selection pool. No automatic achievement completion or new
difficulty modes were added.

## Achievement and mode coverage

Read the local Map, MapDifficulty, LFGDungeons, Achievement, Criteria,
CriteriaTree and ModifierTree extracts. The inventory contains 116 instance/raid
map records, including old and unused maps; 106 have mapped loot sources. The
checked map-bound achievements contain 1,729 criteria associations across 1,188
achievements/statistics. None had a missing criterion modifier root.

All 278 checked criteria associations for 173 achievements named `Heroic:` reject
Normal difficulty. This includes both 10- and 25-player Normal raid checks. The
projection evaluates the actual modifier tree's AND/OR/NOT structure, legacy
difficulty condition 20, map difficulty condition 68 and nested modifier links.
Other conditions remain unknown rather than being assumed satisfied. No
achievement difficulty fix was justified by this check.

Dungeon modes use LFGDungeons when available: MapDifficulty also retains unused
Normal entries for Heroic-only Cataclysm dungeons. Older maps with only Normal
were not given invented Heroic achievements. The regular completion achievement
may legitimately also be earned on Heroic, as specified by its client criteria.

## Validation and installation

Tested on `world_instance_rewards_review_20261005`, cloned from the live world
tables. The migration was applied twice and the three changed table checksums
were identical after both applications. SQL checks passed for all selected item
masks, preservation of existing chances/counts/groups, all nine chest masks and
the four added items. The five checks returned zero failures.

Applied to the live database while worldserver was stopped. Backup:
`Build/instance-rewards-audit/world-before-rewards.sql` (the three modified tables).
The existing Win64 server initialized in 23 seconds with an empty DBErrors.log
and shut down normally. These are SQL-only changes; no executable replacement
was necessary. The server is left stopped after the smoke test.

Run from the repository root:

```powershell
& contrib/instance_rewards_548/audit.ps1
& contrib/instance_rewards_548/verify.ps1 # fresh, isolated review schema
# If that schema already exists from this audit:
& contrib/instance_rewards_548/verify.ps1 -ExistingReview
```

`verify.ps1 -Deploy` requires a stopped server, a successful validation hash for
the exact SQL file, and a new backup path. It deliberately refuses to overwrite
the existing backup. Database credentials are read privately from worldserver.conf.

## Limits and remaining review candidates

This is a data/logic audit, not an in-game clear of every encounter. It does not
certify every optional achievement mechanic, timing condition, scripted chest,
bonus-roll currency, personal-loot specialization rule or drop percentage.

The loot traversal checks direct entries and nested reference groups against the
local Dungeon Journal, respecting source spawn masks. Summoned bosses are also
matched by script-bound names. This is not a complete interpreter of encounter
scripts: scripted loot proxies, transport chests, alternate boss identities and
disabled static spawns can produce missing-source candidates. The post-fix
report contains 95 such journal-item/mode candidates across eight maps, including
Ring of Law, the Cache of Madness, Escape from Arthas and Lorewalker Stonestep.
They are not 95 proven missing drops. Some items have obsolete/incomplete journal
mode information. These candidates need encounter/source verification before
further data changes; no guessed drop probabilities were inserted.

Remaining cross-mode journal discrepancies concern Phoenix Hatchling, Blazing
Drake and Gooey Sha-ling, not equipment or tier-token variants. Their cosmetic
drop rules cannot safely be inferred from the journal's mode field alone, so
their existing drops were preserved. Sinestra's unused Normal rows were also not
converted into additional Heroic rolls: her actual Heroic loot already uses
reference tables. Likewise, unsupported Regular-mode remnants were not promoted
to new raid rewards.

Raw, local reports: `Build/instance-rewards-audit/deployed/`. The checked mode
inventory is retained in `contrib/instance_rewards_548/instances.tsv`.

Binary layouts were cross-checked against the versioned
[JournalEncounterItem definition](https://github.com/wowdev/WoWDBDefs/blob/master/definitions/JournalEncounterItem.dbd),
[JournalEncounter definition](https://github.com/wowdev/WoWDBDefs/blob/master/definitions/JournalEncounter.dbd)
and [JournalInstance definition](https://github.com/wowdev/WoWDBDefs/blob/master/definitions/JournalInstance.dbd).
Journal bit positions and server Difficulty bit positions are different; the
audit explicitly translates them instead of copying masks between tables.
